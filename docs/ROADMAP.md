# Roadmap

**Current:** v0.2.1 — static site, documentation hub, mirrored `/docs` artifacts, contributing and changelog for a trustworthy public standard repo.

## Not Yet

Narrow scope is a discipline, not a shortage of ambition. The following are intentionally excluded right now so the Bridge stays legible and accountable without pretending to be a platform:

- **No marketplace yet** for models, prompts, or “creative assets.”
- **No payments yet**—no billing, subscriptions, or escrow.
- **No messaging yet**—no in-product chat, DMs, or notifications.
- **No public collaborator tagging yet**—no social graph, discovery feeds, or profile pages.
- **No AI asset hosting yet**—the site does not store generated media for teams.

## Near term

- **v0.1.x — Clarity pass:** tighten copy from community feedback; add FAQ only if it removes repeated confusion.
- **Examples:** one exemplar `project.json` and `collaborator.json` per tier band (documentation-only).

## Medium term

- **Validation tooling:** small CLI or CI recipe that validates metadata against JSON Schema.
- **Badge set:** minimal SVG badges for README use (tier + standard version), no tracking pixels.

## Longer term

- **Pattern library:** short, reusable brief templates and checkpoint checklists—still optional, still human-led.
- **Localized summaries:** translate the Standard’s commitments where volunteers maintain accuracy.

## Explicit non-goals

- Building a generative model marketplace.
- Automated “ethics scoring” of creative output.
- Replacing contracts, unions, or professional guild guidance.

## How to propose changes

Open a discussion or pull request with: problem statement, proposed text diff, and migration impact on schema version fields.

## v0.2.1 Project Profile Readiness Pass

Adds a checklist and example scorecard so project profiles can be reviewed for transparency, role clarity, artist respect, and human-finished pathways.

This remains static and non-certifying. It does not introduce accounts, messaging, marketplace behavior, verification, or public collaborator tagging.

## v0.3.0 Creator Submission Packet

Adds a static preparation packet for creators to describe AI-assisted projects before any outreach or collaboration.

This keeps the project non-platform: no forms, accounts, messaging, payments, marketplace behavior, certification, or public collaborator tagging.

## v0.4.0 Collaborator Profile Packet

Adds a static collaborator-side packet so artists and other contributors can clarify role lanes, AI-adjacent comfort, credit expectations, contact boundaries, and opt-in discovery preferences.

This remains non-platform: no accounts, public profiles, messaging, marketplace behavior, hiring workflows, public collaborator tagging, or implied project attachment.

## v0.5.0 Public Trust Layer

Adds a public trust layer so the project’s anti-replacement stance, disclosure model, consent boundaries, credit boundaries, accessibility framing, and non-platform discipline are visible in one place.

This makes the project easier to inspect and criticize before any platform behavior exists.

## v0.6.0 Governance Layer

Adds static governance so future changes can be reviewed against versioning rules, change proposal expectations, rejected patterns, and escalation triggers.

This keeps accounts, submissions, messaging, payments, public profiles, marketplace behavior, certification, verification, and AI asset hosting behind explicit review.
